# "공개"의 수준 구분하기

"오픈소스 모델"이라는 말은 서로 매우 다른 것을 가리킨다. 공부 대상을 고르기 전에 **무엇이 공개됐는지**를 구성요소별로 따져 보는 습관을 들인다.

## 1. 모델 하나를 이루는 것들

| 구성요소 | 예 | 없으면 못 하는 것 |
|---|---|---|
| **가중치** (최종 파라미터) | `model.safetensors` | 실행 자체 |
| 추론 코드·모델 구조 | `config.json`, 모델 클래스 | 가중치를 올바르게 실행 |
| 토크나이저 | `tokenizer.json` | 텍스트 ↔ 토큰 변환 |
| **학습 코드와 설정** | 학습 스크립트, 하이퍼파라미터 파일 | 재학습, "왜 이렇게 됐나"의 추적 |
| **학습 데이터** (또는 그것을 다시 만드는 절차) | 데이터셋, 수집·필터링 코드 | 모델이 무엇을 봤는지 확인, 데이터 영향 분석 |
| 데이터 처리 코드 | 중복 제거, 품질 필터, 혼합 비율 | 데이터 파이프라인 재현 |
| **중간 체크포인트** | 학습 단계별 가중치 | 학습 과정의 관찰 |
| 학습 로그 | 손실 곡선, 실험 기록 | 내 재현이 맞는지 대조 |
| 평가 코드와 데이터 | 벤치마크 스크립트 | 논문 숫자의 재현 |
| 문서 | 논문·보고서, 모델 카드, 데이터 카드 | 위 모든 것의 해석 |
| 라이선스 | Apache-2.0, MIT, 자체 라이선스 | 무엇을 해도 되는지 판단 |

## 2. 세 가지 수준

이 폴더에서는 다음 세 수준으로 나눠 부른다.

| 수준 | 공개된 것 | 할 수 있는 공부 | 예 (2026-11 확인) |
|---|---|---|---|
| **A. 가중치 공개 (open-weight)** | 가중치 + 추론 코드 + 보고서. 학습 데이터와 전체 학습 코드는 비공개 | 추론, 미세조정, 내부 분석(해석가능성) | Llama, Gemma, Qwen, DeepSeek, gpt-oss, Phi, Mistral, K-EXAONE, A.X, Solar Open, Kanana, HyperCLOVA X SEED |
| **B. 대부분 공개** | A + 학습 코드·설정 + 데이터 구성 정보(공개 데이터 위주) + 일부 체크포인트 | A + 학습 절차 읽기, 부분 재현 | SmolLM2, SmolLM3, OpenCLIP |
| **C. 완전 공개 (fully open)** | 데이터(또는 재현 가능한 파이프라인) + 코드 + 가중치 + 중간 체크포인트 + 로그 | B + 학습 과정 관찰, 데이터→행동 추적, 처음부터 재학습 | Pythia, OLMo 2, Olmo 3, Apertus, KORMo(한국어·영어), LLM360(Amber 등), Marin, nanoGPT·nanochat으로 직접 학습한 모델 |

경계는 칼로 자르듯 나뉘지 않는다. 같은 B 수준이라도 무엇이 빠졌는지는 모델마다 다르다. 그래서 **수준 이름보다 아래 체크리스트의 답**이 중요하다.

## 3. 공식적인 기준 두 가지

### 오픈소스 AI 정의 1.0 (Open Source Initiative, 2024)
[OSAID 1.0](https://opensource.org/ai/open-source-ai-definition)은 오픈소스 AI를 "사용·연구·수정·공유"의 네 자유를 주는 시스템으로 정의하고, 그러려면 **수정하기에 적합한 형태**로 다음 세 가지가 모두 제공되어야 한다고 말한다.

| 요소 | 요구 사항 (요약) |
|---|---|
| **Data Information** | 숙련된 사람이 실질적으로 동등한 시스템을 만들 수 있을 만큼 상세한 학습 데이터 정보: 전체 데이터의 설명(출처·범위·수집과 선택 방법·라벨링·처리와 필터링), 공개 데이터의 목록과 입수처, 제3자에게서 구할 수 있는 데이터의 목록과 입수처 |
| **Code** | 시스템을 학습하고 실행하는 데 쓰인 **완전한 소스 코드**: 데이터 처리·필터링 코드, 학습 코드(인자와 설정 포함), 검증·테스트, 토크나이저 같은 지원 라이브러리, 추론 코드, 모델 구조 |
| **Parameters** | 가중치 등 모델 파라미터. 예로 주요 중간 단계의 체크포인트와 최종 옵티마이저 상태를 든다 |

눈여겨볼 점: 데이터 **자체**의 공개까지 요구하지는 않고 "데이터 정보"를 요구한다. 그리고 **가중치만 공개한 모델은 이 정의를 충족하지 않는다.**

### Model Openness Framework (Linux Foundation, 2024)
[MOF](https://arxiv.org/abs/2403.13784)는 모델 개발 과정의 구성요소 17개를 정하고, 공개된 범위에 따라 세 등급으로 나눈다([판정 도구](https://isitopen.ai/)).

| 등급 | 이름 | 포함해야 하는 것 |
|---|---|---|
| Class III | Open Model | 모델 구조, 최종 파라미터, 기술 보고서 또는 논문, 평가 결과, 모델 카드, 데이터 카드 |
| Class II | Open Tooling | Class III 전부 + 학습·검증·테스트 코드, 추론 코드, 평가 코드, 평가 데이터, 지원 라이브러리·도구 |
| Class I | Open Science | Class II 전부 + 연구 논문, **데이터셋**, 데이터 전처리 코드, **중간 체크포인트** |

Class I이 이 폴더에서 말하는 "완전 공개"에 가장 가깝다.

### 독립적인 평가
- [European Open Source AI Index](https://osai-index.eu/): 생성 모델들을 항목별로 평가해 공개하는 목록. 2026-08-27 갱신본의 목록 앞쪽에는 YuLan-Mini, Apertus, BLOOMZ, OLMo(Olmo 3), SmolLM3, Amber(LLM360), Pythia 등이 올라 있다.
- Liesenfeld et al. (2023) *[Opening up ChatGPT](https://arxiv.org/abs/2307.05532)*: "오픈소스"를 표방하는 프로젝트들을 코드·학습 데이터·가중치·RLHF 데이터·라이선스·문서·접근 방법으로 나눠 점검한 논문. 결론은 **공개성은 정도의 문제**이고, 이름만 오픈인 경우(open-washing)가 많다는 것이다.

## 4. 판별 체크리스트 (모델 하나에 10분)

모델 카드와 저장소를 열고 아래에 답한다. 답을 [모델 해부 노트](../_templates/model_study.md)의 1절에 적는다.

| # | 질문 | 확인하는 곳 |
|---|---|---|
| 1 | 가중치를 로그인·승인 없이 받을 수 있는가 | Hugging Face 모델 페이지의 gated 표시 |
| 2 | 라이선스는 무엇이고, 상업적 이용·재배포·수정에 제한이 있는가 | 모델 카드의 `license`, LICENSE 파일 |
| 3 | **학습** 코드가 있는가 (추론 코드만 있는 것은 아닌가) | 저장소에서 `train`, `pretrain` 스크립트와 설정 파일 |
| 4 | 학습 데이터를 내려받을 수 있는가. 아니라면 다시 만드는 절차가 있는가 | 모델 카드의 `datasets`, 데이터 저장소, 처리 코드 |
| 5 | 데이터 혼합 비율·필터링 기준이 적혀 있는가 | 논문의 데이터 절, 설정 파일 |
| 6 | 하이퍼파라미터 전체가 있는가 (학습률 스케줄, 배치 크기, 총 토큰 수, 옵티마이저) | 설정 파일, 논문 부록 |
| 7 | 중간 체크포인트가 있는가 | 모델 저장소의 revision(브랜치), 별도 체크포인트 저장소 |
| 8 | 학습 로그(손실 곡선 등)를 볼 수 있는가 | W&B 링크, 저장소의 로그 |
| 9 | 평가를 재현할 코드와 설정이 있는가 | 평가 저장소, 프롬프트 형식 |
| 10 | 후처리 학습(SFT·선호 학습·RL)의 데이터와 코드도 공개됐는가 | instruct/chat 모델의 카드 |

3~10번에서 "예"가 많을수록 완전 공개에 가깝다. **10번은 자주 빠진다.** 사전학습은 공개해도 채팅 모델로 만드는 단계는 비공개인 경우가 많다.

## 5. 라이선스 읽는 법 (최소한)

| 종류 | 예 | 의미 |
|---|---|---|
| 허용적 오픈소스 라이선스 | Apache-2.0, MIT | 사용·수정·재배포·상업적 이용 가능 (고지 의무 정도) |
| 자체(커뮤니티) 라이선스 | Hugging Face에서 `license: other` 로 표시되는 것들 | 조건이 모델마다 다르다. 이용 목적·규모·재배포에 제한이 있을 수 있으니 **원문을 읽는다** |
| 데이터 라이선스 | CC-BY, CDLA, ODC-By 등 | 가중치와 **별개로** 데이터에 붙는다 |

2026년 11월 Hugging Face 모델 카드 기준으로, 이 문서에서 언급한 모델의 라이선스 표시는 다음과 같다.

| 모델 | 표시된 라이선스 | 수준 |
|---|---|---|
| Olmo 3 (7B Instruct), OLMo 2 (1B) | Apache-2.0 | C |
| KORMo-10B (한국어·영어) | Apache-2.0 | C |
| Pythia-70m | Apache-2.0 | C |
| Apertus v1.5 8B | Apache-2.0 (받을 때 약관 동의 절차 있음) | C |
| nanochat-d32 (예시 가중치) | MIT | C |
| SmolLM2-135M, SmolLM3-3B | Apache-2.0 | B |
| gpt-oss-20b, Qwen3.8-27B, Gemma 4 (12B) | Apache-2.0 | A |
| DeepSeek-V4.1-Flash, Phi-4 | MIT | A |
| K-EXAONE-2.0, A.X-K2 | Apache-2.0 | A |
| Llama 4, Mistral Large 4, Solar Open2, Kanana 2, HyperCLOVA X SEED | other (자체 라이선스) | A |

**라이선스가 Apache-2.0이라고 해서 완전 공개인 것은 아니다.** 라이선스는 "공개된 것을 어떻게 써도 되는가"를, 공개 수준은 "무엇이 공개됐는가"를 말한다. 두 축은 별개다.

## 6. 왜 이 구분이 공부에 중요한가

- **A 수준**만으로도 추론·미세조정·해석가능성 공부는 충분히 할 수 있다. 다만 "이 능력이 어떤 데이터에서 왔는가", "학습 중 언제 생겼는가"는 답할 수 없다.
- **C 수준**에서는 가설을 세우고 확인할 수 있다. 예: "이 모델이 날짜 계산을 못하는 것은 데이터에 그런 예가 적어서인가?" → 데이터에서 직접 세어 본다. Ai2는 Olmo 3와 함께 모델 출력을 학습 데이터로 거슬러 추적하는 도구(OlmoTrace)를 제공한다.
- 그리고 **가장 완전한 공개는 내가 직접 학습한 모델**이다. 규모는 작아도 모든 결정을 내가 했고 모든 것을 바꿔 볼 수 있다. 그래서 이 트랙은 직접 학습(lab02)에서 시작한다.
