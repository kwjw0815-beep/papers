# 공부 내용 — 데이터에서 가중치까지, LLM이 만들어지는 전 과정

언어모델 하나가 만들어지는 과정을 순서대로 따라간다. 각 절은 **무엇을 하는 단계인가 → 알아야 할 개념 → 공개 모델에서 직접 볼 수 있는 곳 → 확인 질문**으로 되어 있다.
개념 설명은 최소한으로 하고, "어디를 열어 보면 실제 모습이 나오는가"에 무게를 둔다.

```
[1 데이터] → [2 토크나이저] → [3 모델 구조] → [4 사전학습] → [5 중간학습] → [6 후처리 학습] → [7 평가] → [8 공개] → [9 추론]
  수집·정제      텍스트→토큰      파라미터 배치     다음 토큰 예측    어려운 데이터      SFT → 선호학습 → RL     벤치마크      가중치·카드     샘플링·양자화
```

먼저 큰 그림을 영상으로 보고 오면 좋다: Karpathy, [*Deep Dive into LLMs like ChatGPT*](https://www.youtube.com/watch?v=7xTGNNLPyMI)

## 1. 데이터: 무엇을 읽혀서 만드는가

**하는 일.** 웹·코드·논문·책 등에서 텍스트를 모으고, 걸러내고, 섞는다. 모델의 지식과 말투, 편향의 대부분이 여기서 정해진다.

**알아야 할 개념**
| 개념 | 뜻 |
|---|---|
| 수집 (crawl) | 웹 아카이브(Common Crawl 등)에서 원문을 얻는다. 수집을 거부한 사이트(robots.txt)를 어떻게 다루는지가 쟁점이다 |
| 텍스트 추출 | HTML·PDF에서 본문만 꺼낸다. PDF는 OCR 모델을 쓰기도 한다 |
| 중복 제거 (deduplication) | 같은·거의 같은 문서를 지운다. 안 하면 모델이 흔한 문서를 외운다 |
| 품질 필터 | 언어 식별, 길이·반복 규칙, 분류기 점수로 저품질 문서를 걸러낸다 |
| 혼합 (mix) | 출처별 비율을 정한다. "웹 몇 %, 코드 몇 %, 수학 몇 %" |
| 오염 제거 (decontamination) | 평가 문제가 학습 데이터에 들어 있으면 지운다 |
| 합성 데이터 | 다른 모델이 생성한 데이터. 작은 모델용 데이터(TinyStories)나 후처리 학습 데이터에 많이 쓰인다 |

**공개 모델에서 볼 수 있는 곳**
- **Olmo 3**: 사전학습 말뭉치 Dolma 3(약 9.3조 토큰)에서 약 6조 토큰짜리 학습 혼합(Dolma 3 Mix)을 만들었다고 공개했고, 정제 도구(datamap-rs), 중복 제거 도구(duplodocus), 평가 문제 제거 도구(decon)도 공개했다. → [Ai2 블로그](https://allenai.org/blog/olmo3), 논문 *[Dolma](https://arxiv.org/abs/2402.00159)* (앞선 버전의 데이터 구축 과정)
- **Pythia**: 모든 모델이 the Pile을 **같은 순서로** 봤고, 토큰화된 데이터와 데이터 로더 재구성 스크립트가 공개되어 있다. "이 문장을 몇 번째 스텝에서 봤는가"를 따질 수 있다.
- **SmolLM2**: 기존 데이터가 작거나 품질이 낮은 단계를 위해 새 데이터셋(FineMath, Stack-Edu, SmolTalk)을 만들었고, 이전 단계의 성능을 보고 다음 단계의 혼합 비율을 **손으로 조정**했다고 논문에 적혀 있다.
- **Apertus**: 공개적으로 이용 가능한 데이터만 쓰고, robots.txt의 수집 거부를 소급 적용하며, 비허용 라이선스·유해·개인정보 콘텐츠를 걸렀다고 밝힌다.
- **FineWeb**: 웹 데이터를 단계별로 정제하며 각 필터의 효과를 ablation으로 보인 데이터 논문 → *[The FineWeb Datasets](https://arxiv.org/abs/2406.17557)*
- 직접 열어 보기: Hugging Face의 데이터셋 뷰어에서 [TinyStories](https://huggingface.co/datasets/roneneldan/TinyStories), [fineweb-edu](https://huggingface.co/datasets/HuggingFaceFW/fineweb-edu), [smoltalk](https://huggingface.co/datasets/HuggingFaceTB/smoltalk)의 실제 행을 읽는다.

**확인 질문**
1. 학습 데이터 100행을 직접 읽어 보라. 예상보다 품질이 어떤가? 어떤 종류의 문서가 가장 많은가?
2. 중복 제거를 하지 않으면 모델의 어떤 행동이 달라질까? (Pythia는 중복 제거한 버전과 안 한 버전을 둘 다 공개했다.)
3. "평가 데이터가 학습 데이터에 섞였는지"를 가중치만 공개된 모델에서는 어떻게 확인할 수 있을까? 확인할 수 없다면 그 모델의 벤치마크 점수를 어떻게 읽어야 하나?

## 2. 토크나이저: 텍스트를 숫자로

**하는 일.** 텍스트를 토큰 번호의 나열로 바꾸는 규칙을 데이터에서 학습한다(대개 BPE). 한 번 정하면 모델과 평생 함께 간다.

**알아야 할 개념:** 바이트 수준 BPE, 어휘 크기(수만~수십만), 특수 토큰(문서 시작, 채팅의 역할 구분 토큰), **채팅 템플릿**(대화를 하나의 토큰열로 펴는 형식).

**직접 볼 수 있는 곳**
- [LLM Lab 01](../04_NLP_LLM/labs/lab01_tokenizer_attention_from_scratch.ipynb) 1절: BPE를 30줄로 구현
- [lab01](labs/lab01_inspect_open_model.ipynb): 공개 모델의 토크나이저로 한국어·영어를 쪼개 본다
- nanochat: `scripts/tok_train.py`(토크나이저 학습), `scripts/tok_eval.py`(압축률 평가)
- 모델 저장소의 `tokenizer.json`, `tokenizer_config.json`(채팅 템플릿이 들어 있다)

**확인 질문**
1. 같은 한국어 문장이 영어 중심 토크나이저와 다국어 토크나이저에서 각각 몇 토큰인가? 비용과 문맥 길이에 어떤 영향이 있나?
2. 채팅 모델에 채팅 템플릿을 적용하지 않고 문장만 넣으면 어떻게 되는가? (직접 해 볼 것)

## 3. 모델 구조: 파라미터를 어디에 두는가

**하는 일.** 디코더 전용 Transformer를 몇 층, 얼마나 넓게 쌓을지 정한다. 2017년 원형과 비교하면 요즘 모델은 몇 가지 부품이 바뀌었다.

| 부품 | 2017 Transformer | 요즘 흔한 선택 | 이유 |
|---|---|---|---|
| 정규화 위치 | 하위 층 **뒤** (post-norm) | 하위 층 **앞** (pre-norm) | 깊은 모델의 학습 안정성 |
| 정규화 종류 | LayerNorm | RMSNorm | 더 단순하고 빠름 |
| 위치 정보 | 사인파를 입력에 더함 | RoPE(회전 위치 임베딩) | 상대 위치, 긴 문맥으로의 확장 |
| 활성화 / FFN | ReLU | SwiGLU 등 게이트형 | 같은 파라미터에서 더 좋은 성능 보고 |
| 어텐션 | 헤드마다 Q·K·V | GQA(여러 Q 헤드가 K·V를 공유) | 추론 메모리(KV 캐시) 절감 |
| 큰 모델 | 모든 파라미터가 매번 동작(dense) | MoE(토큰마다 일부 전문가만 동작) | 총 파라미터 대비 계산량 절감 |

관련 논문: [RoPE](https://arxiv.org/abs/2104.09864), [RMSNorm](https://arxiv.org/abs/1910.07467), [GLU 변형(SwiGLU)](https://arxiv.org/abs/2002.05202), [GQA](https://arxiv.org/abs/2305.13245)

**직접 볼 수 있는 곳**
- [lab01](labs/lab01_inspect_open_model.ipynb) 1~2절: `config.json`과 파라미터 이름에서 위 선택들을 찾아낸다
- [lab02](labs/lab02_train_tiny_gpt_end_to_end.ipynb) 3절: 구조를 직접 코드로 쓴다
- nanoGPT `model.py`(약 300줄, GPT-2 구조), nanochat `nanochat/gpt.py`(현대적 변형)
- SmolLM3 모델 카드: "GQA와 NoPE(3:1 비율)를 쓰는 디코더 전용 Transformer"라고 구조를 요약한다
- 모델 이름 읽기: `K-EXAONE-2.0-750B-A37B` 같은 이름의 `A37B`는 MoE 모델에서 토큰 하나를 처리할 때 **활성화되는** 파라미터 수를 뜻하는 표기다

**확인 질문**
1. 폭 $d$, 층 수 $L$, 어휘 $V$ 인 GPT류 모델의 파라미터 수를 어림하는 식을 써 보라. (힌트: 블록 하나는 어텐션 약 $4d^2$ + FFN 약 $8d^2$)
2. 내가 고른 모델의 config에서 위 표의 선택지를 각각 찾아 적어 보라.

## 4. 사전학습: 다음 토큰 맞히기

**하는 일.** 수조 개의 토큰에 대해 "다음 토큰의 확률"을 맞히도록 가중치를 갱신한다. 비용의 대부분이 여기서 든다.

**알아야 할 개념**
| 개념 | 뜻 | 실무적 의미 |
|---|---|---|
| 목적 함수 | 다음 토큰에 대한 교차 엔트로피 | 손실 $L$ → perplexity $e^L$. 초기값은 약 $\ln V$ |
| 옵티마이저 | AdamW가 표준. 최근 공개 학습 코드에는 Muon을 함께 쓰는 예도 있다 | [dl Lab 02](../03_Deep_Learning/labs/lab02_training_dynamics.ipynb) 1절 |
| 학습률 스케줄 | warmup 뒤 감소(코사인 등) | 처음에 너무 크면 발산, 끝에는 작게 |
| 기울기 클리핑 | 기울기의 크기를 제한 | 드문 폭주로부터 보호 |
| 배치 크기 | 토큰 수로 센다(예: 스텝당 수백만 토큰) | 장비 하나에 안 들어가면 기울기 누적·분산 학습 |
| 혼합 정밀도 | bfloat16 등으로 계산 | 메모리와 속도 |
| 체크포인트 | 일정 간격으로 가중치 저장 | 재시작, 그리고 **학습 과정의 관찰** |
| 계산 예산 | 파라미터 수 × 토큰 수가 대략 비용을 정한다 | *[Chinchilla](https://arxiv.org/abs/2203.15556)*: 주어진 계산량에서 모델 크기와 데이터 양을 함께 키워야 한다 |

**직접 볼 수 있는 곳**
- [lab02](labs/lab02_train_tiny_gpt_end_to_end.ipynb) 4~5절: 학습 루프와 손실 곡선
- nanoGPT `train.py`: 학습률 스케줄 함수, 기울기 누적, 체크포인트 저장을 한 파일에서 본다
- nanochat: `scripts/base_train.py`. README는 깊이(`--depth`) 하나로 나머지 하이퍼파라미터가 정해지도록 설계했다고 설명하고, 검증 지표로 **bits per byte**(어휘 크기와 무관한 손실 단위)를 쓴다
- Pythia: 모델 크기별 학습률·배치 크기 표가 저장소 README에 있고, 학습 로그(W&B)가 링크되어 있다
- Olmo 3: 최대 1,024개의 H100으로 사전학습했다고 밝히며, 공식 학습 스크립트가 OLMo-core 저장소에 있다
- [modded-nanogpt](https://github.com/KellerJordan/modded-nanogpt): 같은 목표 손실에 더 빨리 도달하는 기록 경쟁. 기록이 갱신될 때마다 "무엇을 바꿨는지"가 남아 있어 최적화 기법의 목록처럼 읽을 수 있다

**확인 질문**
1. 내 모델의 초기 손실이 $\ln V$ 와 크게 다르다면 무엇이 잘못됐을 가능성이 있나?
2. 학습률 warmup을 없애면 어떻게 되는지 lab02에서 실험해 보라.
3. 같은 계산 예산이라면 "큰 모델을 짧게"와 "작은 모델을 길게" 중 무엇이 나은가? Pythia나 Marin의 Delphi 실험(여러 크기 × 여러 학습량)에서 근거를 찾아보라.

## 5. 중간학습(mid-training): 어려운 데이터로 마무리

**하는 일.** 사전학습의 끝부분이나 직후에, 수학·코드·추론·지시 따르기처럼 **목표 능력에 가까운 고품질 데이터**의 비중을 높여 더 학습한다. 최근 공개 모델들이 공통으로 두는 단계다.

**직접 볼 수 있는 곳**
- **OLMo 2**: 학습 후반에 특화 데이터 혼합(Dolmino Mix)을 넣는 "late-stage curriculum"을 설명한다.
- **Olmo 3**: 사전학습을 세 단계로 설명한다 — 넓은 데이터로의 초기 학습, 수학·코드·독해 등 어려운 자료에 집중하는 중간학습(약 1,000억 토큰), 긴 문서로 학습하는 긴 문맥 확장(약 500억 토큰). 단계마다 체크포인트를 공개한다.
- **SmolLM3**: 사전학습 뒤 추론 데이터 약 1,400억 토큰으로 중간학습을 했다고 모델 카드에 적혀 있다.
- **nanochat**: 저장소 구성이 사전학습(`base_train`) → 대화 형식 학습(`chat_sft`)으로 이어진다.

**확인 질문:** 중간학습 전후의 체크포인트가 둘 다 공개된 모델을 골라, 같은 수학 문제 5개를 풀게 해 보라. 무엇이 달라졌나?

## 6. 후처리 학습(post-training): 말 잘 듣는 모델로

사전학습만 한 모델(base model)은 "이어 쓰기"만 한다. 질문에 답하고 지시를 따르는 모델로 만드는 과정이 후처리 학습이다. 보통 세 단계를 차례로 쓴다.

| 단계 | 하는 일 | 데이터의 모양 | 참고 |
|---|---|---|---|
| **SFT** (지도 미세조정) | 대화 예시를 그대로 따라 하도록 학습 | (지시, 모범 응답) 쌍 | 채팅 템플릿으로 펴서 다음 토큰 예측 |
| **선호 학습** (DPO 등) | 좋은 응답과 나쁜 응답 중 좋은 쪽의 확률을 높임 | (프롬프트, 선호 응답, 비선호 응답) | *[DPO](https://arxiv.org/abs/2305.18290)*, SmolLM3는 APO라는 변형을 썼다고 밝힌다 |
| **RL** (검증 가능한 보상) | 정답을 자동으로 채점할 수 있는 문제(수학, 코드)에서 보상으로 학습 | 문제 + 채점기 | *[DeepSeek-R1](https://arxiv.org/abs/2501.12948)*, OLMo 2·Olmo 3의 RLVR |

**직접 볼 수 있는 곳**
- **Olmo 3**: Think / Instruct / RL-Zero 경로 각각에 대해 SFT → DPO → RLVR 단계별 체크포인트가 Hugging Face에 있고(예: `Olmo-3-7B-Instruct-SFT`, `-DPO`), 후처리 데이터 모음(Dolci)과 코드(open-instruct)가 공개되어 있다.
- **Apertus v1.5**: `-SFT`, `-DPO`, `-RL` 체크포인트가 따로 올라와 있다.
- **nanochat**: `scripts/chat_sft.py`, `scripts/chat_rl.py`, 과제 정의는 `tasks/` (GSM8K, MMLU, SmolTalk 등).
- 이 문서의 5~7단계 과제
- 가중치만 공개된 모델의 경우: 이 단계의 데이터와 절차는 대부분 비공개다. [체크리스트](01_openness-levels.md#4-판별-체크리스트-모델-하나에-10분) 10번.

## 7. 평가: 얼마나 좋은지 재기

**하는 일.** 고정된 문제 세트에서 점수를 낸다. 숫자 자체보다 **어떤 조건에서 잰 숫자인지**가 중요하다.

**알아야 할 개념**
| 개념 | 뜻 |
|---|---|
| 손실·perplexity·bits per byte | 사전학습 단계의 기본 지표. 토크나이저가 다르면 손실끼리 비교할 수 없어 bits per byte를 쓴다 |
| 객관식 벤치마크 | 선택지별 확률을 비교하거나 생성된 답을 채점 |
| 생성형 평가 | 코드 실행, 정답 문자열 일치, LLM 채점 |
| 평가 조건 | 프롬프트 형식, few-shot 예시 수, 채팅 템플릿 사용 여부, 샘플링 온도 — **이것이 다르면 숫자가 달라진다** |
| 통계 | 문항 수에 따른 표준오차, 반복 실행의 평균 → [LLM Lab 03](../04_NLP_LLM/labs/lab03_llm_eval_error_bars.ipynb) |
| 오염 | 평가 문제가 학습 데이터에 있었는가 |

**직접 볼 수 있는 곳**
- nanochat: `scripts/base_eval.py`(CORE 점수), `scripts/chat_eval.py`. README의 리더보드는 "GPT-2의 CORE 점수를 넘기까지 걸린 시간"을 잰다 — **목표 성능을 고정하고 비용을 비교하는** 평가 설계의 예다.
- Olmo 3: 평가 도구 OLMES와 평가 모음을 공개했고, 블로그의 결과 표는 "3회 실행의 평균"임을 밝힌다.
- 표준 도구: [lm-evaluation-harness](https://github.com/EleutherAI/lm-evaluation-harness)
- 이 문서의 5~7단계 과제

**확인 질문**
1. 모델 카드의 벤치마크 표 하나를 골라, 평가 조건(프롬프트, few-shot 수, 반복 횟수)이 어디에 적혀 있는지 찾아보라. 없다면 그 숫자를 다른 모델의 숫자와 비교해도 되는가?
2. 문항이 200개인 벤치마크에서 2%p 차이는 의미가 있는가?
